# Уведомления о заявках: Telegram (через Make) и SMS

Схема:

```
Форма на сайте → /api/notify.php (Jino) ─┬→ вебхук Make → Router → Telegram-бот → чат администраторов
                                          └→ SMS.ru → SMS на телефон админа
```

Каналы независимы: если один не сработал, заявка всё равно принимается, если сработал другой.

Хостинг сам в Telegram не ходит: PHP-скрипт проверяет заявку (обязательные поля, телефон,
защита от ботов и от спама — не больше 5 заявок за 10 минут с одного адреса) и пересылает её
в Make. Адрес вебхука хранится только на сервере и в коде сайта не виден.

Типы заявок: `booking` — бронь стола, `order` — заказ доставки.

## 1. Telegram-бот и чат

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя
   (например, «Охотник — заявки») и логин бота (`ohotnik_oz_orders_bot`).
2. BotFather пришлёт **токен** вида `123456:ABC...`. Никому его не пересылайте — он понадобится только в Make.
3. Создайте группу «Охотник — заявки», добавьте в неё бота и всех, кому нужны уведомления.
   Можно сделать две группы: «Брони» и «Доставка» — Make умеет слать их в разные чаты.
4. Узнайте **ID чата**: добавьте в группу бота [@getmyid_bot](https://t.me/getmyid_bot)
   (или [@RawDataBot](https://t.me/RawDataBot)) — он пришлёт ID вида `-1001234567890`. Потом его можно удалить.

## 2. Сценарий в Make

1. **Create a new scenario**.
2. Первый модуль: **Webhooks → Custom webhook** → *Add* → имя `ohotnik-site`.
   Скопируйте адрес вебхука
   (`https://hook.eu2.make.com/...`).
3. Нажмите **Run once** и отправьте с сайта тестовую бронь (после шага 3 ниже) —
   Make запомнит структуру данных.
4. После вебхука добавьте **Flow Control → Router** с двумя ветками:
   - ветка «Бронь» — фильтр: `type` *Equal to* `booking`;
   - ветка «Доставка» — фильтр: `type` *Equal to* `order`.

   В фильтр **каждой** ветки добавьте второе условие (AND): `secret` *Equal to* ваш секрет
   (см. шаг 3) — так сценарий отбросит запросы не с нашего сайта.
5. В каждую ветку — модуль **Telegram Bot → Send a Text Message or a Reply**:
   - Connection: *Add* → вставьте токен бота;
   - Chat ID: ID группы из шага 1;
   - Text: поле `text` из вебхука (там уже готовое сообщение);
   - Parse mode: **HTML**.
6. Включите сценарий (переключатель **ON**) и выставьте запуск *Immediately*.

Кроме готового `text` в вебхук приходят отдельные поля — их можно использовать в других
модулях (Google Таблицы, CRM, SMS):

| Поле | Бронь | Заказ |
|---|---|---|
| `secret` | секрет из конфига сервера — только для фильтра | |
| `type` | `booking` | `order` |
| `id` | номер заявки, например `031126-A1B2` | |
| `created_at` | дата и время заявки (МСК) | |
| `name`, `phone`, `comment` | имя, телефон `+7 (999) 123-45-67`, комментарий | |
| `date`, `time`, `guests` | дата `10.11.2026`, время, гостей | — |
| `address`, `payment` | — | адрес, способ оплаты |
| `items`, `total` | — | список блюд (`name`, `qty`, `price`, `sum`), сумма в рублях |

## 3. Настройки на сервере

Адрес вебхука и секрет лежат в файле `~/ohotnik-config.php` — **вне папки сайта**, поэтому
деплой его не трогает и снаружи он не открывается.

В панели Jino → контейнер → **Консоль** выполните (подставьте свой адрес вебхука):

```bash
SECRET=$(openssl rand -hex 16); cat > ~/ohotnik-config.php <<EOF
<?php
return [
    'make_webhook_url' => 'https://hook.eu2.make.com/ВАШ_АДРЕС',
    'make_secret' => '$SECRET',
];
EOF
chmod 600 ~/ohotnik-config.php; echo "Секрет для фильтра в Make: $SECRET"
```

Скопируйте выведенный секрет в фильтры веток Router (шаг 2.4).

## 4. SMS админу через SMS.ru

SMS отправляются прямо с сервера, без Make: SMS.ru — российский сервис, хостинг до него достаёт.

1. Зарегистрируйтесь на [sms.ru](https://sms.ru) и пополните баланс (одна SMS — несколько рублей).
2. В личном кабинете → **Программистам** → скопируйте **api_id**.
3. Добавьте в `~/ohotnik-config.php` две строки — в «Доступе к файлам» Jino откройте файл
   `ohotnik-config.php` в корневой папке и допишите внутрь `return [ ... ];`:

   ```php
       'sms_ru_api_id' => 'ВАШ_API_ID',
       'sms_to' => '79991234567',      // несколько номеров — через запятую: '79991234567,79997654321'
   ```

   Для отладки можно добавить `'sms_test' => true,` — SMS.ru будет имитировать отправку
   без списания денег (SMS при этом не придёт).

4. Отправьте тестовую заявку с сайта — на номер из `sms_to` должна прийти SMS.

Текст SMS короткий, чтобы укладываться в 1–2 сообщения:

- `Бронь 031126-33D7: 20.11 19:00, 2 гост. Анна, +7 (916) 111-22-33`
- `Заказ 031126-A1B2: 1 290 ₽, картой. Анна, +7 (916) 111-22-33, ул. Ленина 1`

Ошибки отправки (нет денег, неверный api_id или номер) пишутся в лог ошибок PHP на хостинге.

## Проверка

- Отправьте бронь с сайта — в чат должно прийти сообщение «🍽 Бронь стола».
- Добавьте блюдо в корзину и оформите заказ — придёт «🛵 Заказ доставки».
- Если на сайте ошибка «Приём заявок временно не настроен» — в `~/ohotnik-config.php` нет ни адреса Make, ни настроек SMS.
- Если «Не удалось отправить заявку» — не сработал ни Make (сценарий выключен, адрес вебхука неверный), ни SMS.
  История запусков — в Make, вкладка **History** сценария.

## Локальная разработка

При `npm run dev` заявки по умолчанию **не отправляются**, а только выводятся в консоль браузера
(F12 → Console) — чтобы тесты не попадали в рабочий чат. Для отправки настоящих заявок с локальной
версии создайте в корне проекта файл `.env.local` со строкой

```
VITE_SEND_REQUESTS=true
```

и перезапустите `npm run dev`. Запросы пойдут через прокси Vite на `https://ohotnik-oz.ru/api/notify.php`.
Файл `.env.local` в git не попадает.
